# WhaleLife B 站子插件

推荐、关注动态、搜索和指定链接浏览；按需查看消息中心的回复与点赞；字幕优先，按片段观看普通投稿视频；用户开启后可读取弹幕、点赞、收藏、关注、评论、回复及分享到 QQ；可选自动续期登录。

WhaleLife 交流 QQ 群：**962935021**

## 使用流程

1. 安装并启用网上冲浪父插件 `surf`，将本插件发行目录 `dist/bilibili` 放入宿主 `plugins/surf/sub/bilibili/`，运行 ID 为 `surf/bilibili`。启用后从网上冲浪工作区进入 B 站设置。
2. 匿名可尝试公开推荐、搜索、视频资料和评论。关注动态需要登录。在设置页扫码确认，或导入完整 Cookie；两者校验同一账号信息，能力开关相同。过期或平台风控会明确报告，不自动绕过。
3. 与当前主体说“搜一下 B 站的……”“刷一下关注的视频”或发送链接。先读取简介和可用字幕，再按需观看片段；继续观看使用实际返回的时间覆盖范围。
4. 声音处理默认关闭。关闭时只调用视觉准备，不启动声音识别；启用后才请求现有视觉/视听服务处理语音。视频仍可能需要下载含音轨的完整 MP4，关闭声音减少的是解码/识别开销，不承诺减少同等下载流量。
5. 点赞、收藏、关注、评论、回复均独立开关，初始关闭。开启收藏还须选择本账号收藏夹。互动同时受主干 `full` 工具权限约束；开关由设置页管理，模型不能自行开启。普通浏览不自动收藏或互动。
6. 登录后可说“看看 B 站谁回复了我”或“看看收到的赞”，按需读取平台消息中心并翻页。读取不依赖互动开关，不后台监听，也不主动提交已读。普通视频的回复通知可展开所属楼层；也可从已经读到的评论查看楼中楼。目标评论独立回查，返回根评论、目标评论和当前页回复；有下一页时不声称对话完整。开启回复后，可继续回复目标评论。聚合点赞不保证列出全部点赞者；其他业务或无法可靠定位的通知仅展示。
7. “同步 B 站观看历史”是独立开关，默认关闭。开启后，已登录且有 `full` 权限时，插件在同一次观看调用中自动同步实际采样位置，无需 AI 再调用工具。同步结果随观看一起返回；同步失败仍保留画面。读简介、字幕、只下载视频及未取得有效采样画面均不触发同步。位置采用实际返回画面的最大时间戳，不能填写任意位置或标记看完。它仍是片段采样，不等同于连续播放。
8. “分享到 QQ”独立默认关闭。启用并安装支持该能力的 QQ 插件后，可把刚浏览的视频分享给指定 QQ 好友。分享形式在 QQ 设置的“视频分享方式”中选择：默认图文（封面＋标题＋可点击文字链接），也可选小程序。图文的封面是普通图片，点击文字链接打开视频；小程序的播放及打开 B 站 App 仍有兼容问题。收件人须在 QQ 好友白名单内，当前会话须有完全执行权限。分享只取当前会话的有效视频引用，不需要重新下载视频或登录 B 站。QQ 暂不可用时，普通 B 站浏览不受影响。

插件沿用当前人格、模型和可信工具会话，不另建人格、模型配置、记忆或后台调度。它提供能力；何时主动刷视频仍由已有主体和自主性能力决定。

0.2.10 修复网页登录上下文丢失：扫码保留服务器返回的受支持 Cookie；同账号自动续期合并更新并遵守删除，不再丢掉已有设备信息。旧版本私有设备缓存在对应会话内继续使用，并在该会话续期时带入新的登录态，不跨账号继承。登录、匿名请求交错时按各自凭据串行准备，避免重复申请设备；账号检查、评论和楼中楼读取、可见性复查复用该会话已有设备。续期期间已捕获旧凭据的在途互动会在提交前停止，同账号已有视频引用仍可继续使用。续期中断时，尚未验证的 pending 凭据会保留但暂停用于请求，需要重新确认登录；已经验证、仅确认旧令牌步骤未完成的凭据仍可浏览。该修复不增加模型调用，也不补发历史评论；评论是否公开仍以实际回读为准。

Cookie 保留与更新参考了 [PiliPlus 的账户绑定及响应合并](https://github.com/bggRGjQaUbCoE/PiliPlus/blob/217fb54f51f6764176319bbdedab2a7522d75401/lib/utils/accounts/account_manager/account_mgr.dart#L185) 和 [rongyuio/bilibili 的 Cookie 更新规则](https://github.com/rongyuio/bilibili/blob/1ce2e3b19a059e3d045346eee4010b18cccfc9b8/client.go#L137)，本插件仍使用自己的受限 Cookie 白名单与生命周期实现。

0.2.9 修复评论提交与可见性复核：参考 dsh-bili-whale 1.0.0 的公开实现，评论沿用浏览时的设备 Cookie，并使用 WBI 签名和完整浏览器标识。登录态对应的补充设备标识保存在插件私有数据中，重载后复用，不改账号凭据。提交后在原调用内最多用30秒做两轮匿名查询，必要时用登录态对照；没有查到报告“尚未确认”，不再把提交响应的 state 当成公开证据，不增加主模型调用。未确认公开的已接收动作再次调用时，距上次检查至少30秒才只读复查，始终禁止补发。

请求保护默认串行、请求间隔1.5秒；点赞、收藏、关注、评论、回复共用120秒冷却及每小时12次/每日30次预算。平台明确限流会暂停并尊重 Retry-After；登录/验证码提供恢复路径。历史同步和续期不占互动写额度，媒体下载不占API串行队列。这些是本地保守预算，不是平台安全阈值，也不能保证评论一定公开。只有明确在提交前被本地保护拒绝的动作，才允许下一次主动调用使用原操作编号重试；不会自动发送。评论诊断保存提交编号、目标aid、查询时间及安全状态，不保存评论正文、Cookie、签名URL或主人资料。

0.2.8 修复字幕与视频内容不符：字幕轨道改用 WBI 签名接口，使用当前视频来源页和完整授权地址，失败不回退旧接口；默认优先 AI 中文字幕。补查视频与分P身份，并将同一视频引用的字幕分页固定为一次下载后的内存快照，避免续页切换到变化后的字幕。快照不落盘，换账号、过期或停止即失效；重新打开视频可刷新。结构异常明确报错，不当成“没有字幕”。验证需同时核对台词、视频主题与时间范围，HTTP 200 或可解析 JSON 不代表内容正确。

0.2.7 补齐字幕失败诊断：字幕列表、单条轨道、字幕正文、时间字段和数量限制均有固定阶段、原因、字段类型及位置；部分坏轨道被过滤也留下有界汇总。HTTP/API/传输错误与解析错误共用一次请求的报告，避免重复；诊断不保存字幕正文、签名链接、账号或 Cookie，也不增加模型调用、平台请求或重试。

0.2.6 修正评论和回复的网页来源信息，并在提交取得评论编号后，于同一次调用内做一次不带登录态的可见性回读，最多额外等待5秒，不增加模型调用。结果分别报告当前匿名可见、当前未公开或无法核验；取得评论编号只证明平台接收，不能证明公开，更不能证明 @ 通知送达。读取失败、取消、暂时不可见或审核延迟都不会重发评论；原编号和防重记录保留。旧动作没有可见性证据时显示未知，不重新发送。

0.2.5 增加主人 UID 设置与仅提及主人的评论能力。在设置页填写 UID，点“获取资料并保存”取得昵称与主页；资料保存在本插件，重启后保留。评论或回复可选 `mentionOwner:true`，插件自动添加已配置主人的 @，无需先查资料或再调用另一个工具。默认不提及；未配置主人时拒绝提及。仍需开启评论/回复和 full 权限；模型不能改主人或指定其他 UID，正文不得手写 @。修改主人设置会停止尚未提交的旧提及；清除设置后不能再提及。主人改名时可重新获取。

这里的“记住”是插件持久保存 UID 与昵称，AI 可随时用 `bilibili_owner` 读取；不自动改写人格或聊天记忆。回复他人的评论仍可能触发 B 站原有回复通知，“只 @ 主人”限制的是额外提及对象。平台接收评论、评论公开可见和对方收到 @ 通知是三个不同结果；匿名可见性回读也不能证明通知送达，正式发送仍需实际验收。

0.2.4 改善视频下载兼容性：首次请求即携带 `Range: bytes=0-`，接受经完整性校验的200或206响应。206必须从第0字节覆盖到文件末尾，返回长度、总长度和已知视频大小一致；不把部分文件交给视觉服务。图片下载不受影响，视频下载返回567时会明确提示下载阶段和HTTP状态。没有自动重试或切换下载地址。

0.2.3 将可选历史同步并入观看流程。成功取得合格采样画面后自动提交位置并回读确认，不增加模型轮次；同一位置使用稳定动作编号并沿用持久防重记录。未开启、未登录或权限不足会跳过；同步失败单独报告，不自动补发。原历史工具保留兼容，正常观看不需要再次调用。

0.2.2 修复搜索请求：改用当前 WBI 搜索接口；缺少站点 Cookie `buvid3` 时从 B 站正常接口取得，并使用导航接口下发的键签名。站点 Cookie 和签名键只保存在当前客户端内存，按登录凭据隔离；已有 `buvid3` 优先使用，签名键缓存5分钟。不会修改本地账号文件，失败或需要验证时不自动重试。

0.2.1 增加请求失败诊断。宿主日志中的“B 站请求失败”保留固定接口分类、原始 HTTP 状态、B 站数字错误码、耗时、随机请求编号，以及初始请求是否携带会话 Cookie；后者不代表登录有效。成功请求和二维码正常等待不额外记录。日志不保存搜索词、URL 参数、Cookie、账号资料、视频或评论正文，也不保存平台原始错误说明。旧日志无法补回当时丢失的错误码；新日志可以区分拒绝发生在哪一层，但不能据此断定平台内部风控原因。详见 CONTRACT.md 的诊断字段说明。

0.2.0 增加可选 QQ 视频分享，接入 QQ 插件 0.19.0 的 `videoShareApiVersion: '1.0.0'`、`sendVideoShare` 和 `videoShareDelivery`。QQ 负责按用户设置处理图文或小程序，并提供发送、防重和回执；B 站不覆盖格式、不使用旧小程序入口兜底，不上传视频文件、不模拟网页版分享按钮，也不上报 B 站分享统计。图文封面准备失败时 QQ 可在提交前改为同一条纯文字链接消息；平台提交后不因失败、不确定或取消补发。平台确认不能证明对方已看到、点击或播放成功；保留原动作编号查回执，不自动重发或换格式补发。

0.1.8 移除自动投币，不再提供投币工具、参数或设置开关。旧配置中的 `interactions.coin` 被忽略；旧投币动作记录保留供核对，不重放、不要求清空账本或重新登录。需要投币时请打开 B 站原视频自行操作。

0.1.6 引入的弹幕读取和自动续期继续保留，两个选项独立且默认关闭。弹幕只读普通时间轴文字；续期在使用时按需检查，不设后台任务。

0.1.7 将平台返回的 `-401` 识别为需要验证的访问限制。此时停止操作并提示人工检查，不自动重试或绕过验证。

0.1.5 增加通知展开楼中楼、继续回复，以及可选的观看位置同步。所有引用绑定当前会话与账号，登录变化、过期或重载后失效；关闭历史同步会使已有观看凭据失效。历史提交沿用主干 full 权限，独立保存防重发记录，不能用接口接受代替历史回读确认。

## 能力与限制

| 能力 | 当前范围 |
| --- | --- |
| 入口 | 首页推荐、关注动态中的视频、关键词搜索、BV/av号及普通视频链接/短链 |
| 资料 | 简介、分P、评论、可用字幕；字幕按时间轴分段返回 |
| 消息中心 | 当前登录账号的“回复我的”“收到的赞”，按需查看并翻页；不监听、不主动标记已读 |
| 楼中楼 | 从普通视频回复通知或评论展开；核对视频、评论、作者与根楼层，分页读取，继续回复具体评论 |
| 观看 | 站点提供的单段渐进 MP4，优先低清；可选视觉插件负责画面采样与声音识别 |
| 观看历史 | 默认关闭；开启后在观看调用内自动同步采样位置，区分平台接受、历史确认、跳过和失败 |
| 声音 | 默认关闭；开启时按片段处理语音，具体本地/云端配置由视觉插件管理 |
| 弹幕 | 默认关闭；按视频时间读取普通弹幕，默认0–30秒、单次最多60秒，每页100条，无需下载视频或声音识别 |
| 互动 | 点赞、收藏到选定文件夹、关注UP、评论、回复；评论/回复可选 @ 已配置主人，结果不确定时不自动重发 |
| 主人资料 | 设置 UID 后取得昵称和主页，本插件持久保存，可更新或清除；模型只能读取 |
| 登录续期 | 默认关闭；有刷新凭据时，在实际使用插件前按需检查，设置页只展示状态 |
| QQ 视频分享 | 默认关闭；按 QQ 设置选择图文或小程序，仅支持 QQ 好友白名单；需 QQ 0.19.0 视频分享服务 |
| 未包含 | 投币、直播、番剧、付费专享、私信、发动态及绕过站点验证 |

默认媒体上限 64 MiB（可降低）。实际视觉服务还有时长、容量及单次输出限制；当前单次观看最多60秒、默认30秒。只报告实际采样范围，不能将字幕、下载成功或采样画面说成已完整看完。没有视觉时文字和登录继续可用；没有字幕时明确提示，声音关闭时不自动转写。

观看历史只同步位置，不发送播放心跳、累计观看时长或“已看完”标记，也不保证增加播放量。提交前和提交后核对最近30条普通视频历史；不把未出现在这页视为从未观看，不承诺检测到更早记录或跨设备同时产生的进度。自动同步发生在有效采样画面准备完成后、观看工具返回前，代表已准备这些采样画面，不证明主模型已理解或后续回复成功。取消、停用或更换账号阻止后续请求；已经提交的结果仍保留在回执与台账中，不伪装成未发生。

平台请求目前直连。父服务公开的超时与并发设置可复用；它未公开私有代理地址，因此本插件不会读取父级 data，也不声称 B 站请求继承了父级代理。父级公开搜索/阅读工具仍与 B 站工具共用当前主体。

站内网页 JSON 接口属于当前可观测实现，不是稳定开放 SDK。平台变化、登录限制、网络限制会明确失败；不以空列表掩盖异常，不轮换账号、代理或伪装设备来绕过验证。登录和普通读取也可能被 B 站记录为站点访问；插件不另发观看心跳或伪造完整播放。

自动续期需要刷新凭据，新扫码登录会一起保存；旧登录和单独导入Cookie可能需要重新扫码。开启后成功检查的间隔为24小时，检查失败冷却15分钟；重启会重新检查。先持久保存处理中标记，验证并保存新凭据后才确认旧凭据失效。提交结果不确定或提交后保存失败时暂停续期，须重新登录；不会无限保活，也不保证平台不会主动撤销登录。正常凭据轮换保留当前账号的临时引用，人工登录、导入或退出仍使引用失效。

弹幕取自平台当前分段弹幕池，不保证包含完整历史、已删除、被屏蔽或特殊弹幕。仅返回普通模式1–6的文字及时间，不执行高级/代码弹幕；单片段最多解析12000条，每条最多500字，触及限制会明确报告。翻页会重新读取当前片段，期间平台变化可能影响排序。弹幕不自动加入每次观看，也不写观看历史。

## 数据与权限

本插件 `data/config.json` 保存开关，`data/account.json` 保存本地登录 Cookie、可用的刷新凭据及续期中断状态，`data/actions.json` 保存互动动作散列与实际结果，`data/history-actions.json` 独立保存历史动作散列、位置与状态以防重发。升级到0.1.8保留 `data/actions.json` 中的旧投币记录，读取兼容这些记录但不再执行投币。账号资料仅由设置页提供必要信息，模型工具不接收 Cookie；Cookie 不写入日志、回执或发行物。不读取用户浏览器资料。取消或注销只停止后续使用本地登录态，不承诺撤销远端已完成动作或注销其他设备。

外部资料经临时工具传递，缓存引用绑定会话及账号代际，过期、换号、重载后失效。第三方内容不是授权。视频私有媒体引用不交给模型，声音关闭时无法由本插件返回引用绕过开关。普通聊天最终答复依宿主规则保存，不能承诺所有用户可见回答都不进入历史。

父插件停止时子插件停止；子插件可独立停用。视觉停用只关闭观看，不带停浏览或登录；恢复不自动重放浏览和账号动作。动作提交前先保存记录，已确认回执和不确定结果分别处理；动作记录保存异常时关闭新互动，不能清空记录后盲重发。

平台确认的互动另经公开记忆接口记录一条简短实际经历，不包含第三方正文、URL或评论原文。评论和回复只记录已提交并取得平台回执，不把它写成已公开或已通知对方。记忆写入失败不改变平台成功事实，也不会重发动作；重复核对时可用同一事件标识补记。

历史记录只有本插件确实提交且回读确认后才记录固定的“已同步采样位置”经历，不记录“完整看过”。单纯发现已有进度不冒充新增动作。接口接受但回读未确认、网络结果不确定和确定拒绝分别报告；前两类不自动重发，持久记录损坏或写入失败时停止新历史提交。
